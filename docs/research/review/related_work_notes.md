### 1.1 CRAMF — VERIFIED (reviewer demand #1)

- **Citation:** Wangyue Lu, Lun Du, Sirui Li, Ke Weng, Haozhe Sun, Hengyu Liu,
  Minghe Yu, Tiancheng Zhang, Ge Yu.
  *Automated Formalization via Conceptual Retrieval-Augmented LLMs.*
  arXiv:2508.06931 (v1 2025-08-09; v2 2026-03-21).
  Venue: OpenReview submission exists (forum `09lmwhDqZ3`); **no confirmed
  acceptance found** — cite as arXiv preprint.
- **What it does:** CRAMF ("Concept-driven Retrieval-Augmented Mathematical
  Formalization") builds a concept-definition knowledge base from Mathlib4 —
  26,000+ formal definitions, 1,000+ core mathematical concepts, explicitly
  modeling many-to-many NL-expression↔formal-definition relations —
  constructed by an automated LLM-powered pipeline. At translation time it
  retrieves the formal definitions of the concepts in an informal statement
  and injects them into the autoformalizer's context. On miniF2F, ProofNet,
  and their new AdvancedMath benchmark it reports up to 62.1% (avg 29.9%)
  *relative* improvement in translation accuracy when bolted onto existing
  LLM autoformalizers.
- **Reviewer's description check:** "concept-driven autoformalization with a
  concept-definition knowledge base and retrieval-augmented translation" —
  **accurate**.
- **vs Wikibrain:** the closest prior artifact to the Brain's join. Key
  differences: CRAMF's KB is generated by an unsupervised LLM pipeline (no
  human moderation, no provenance); it joins NL phrases to Mathlib
  *definitions only* (no Wikidata/Wikipedia/external-DB organs, no
  dependency graph); it is **system-side RAG** (context injection into one
  translation call), not tools an autonomous agent chooses to call; its
  baseline is *no-retrieval*, not the same corpora held unjoined — so it
  cannot attribute gains to the join itself; no existence verifier as an
  isolated component; grading is translation accuracy, no kernel-verified
  downstream proving.

### 1.2 Aria — VERIFIED (reviewer demand #2)

- **Citation:** Hanyu Wang, Ruohan Xie, Yutong Wang, Guoxiong Gao, Xintao Yu,
  Bin Dong. *Aria: An Agent for Retrieval and Iterative Auto-Formalization
  via Dependency Graph.* arXiv:2510.04520 (v1 2025-10-06; v2 2026-07-02).
  **ICLR 2026 poster** (iclr.cc virtual poster 10010860; OpenReview
  `CPxZClPMiy`).
- **What it does:** an agent for conjecture-level statement formalization in
  Lean that mimics expert workflow in two phases: recursively decompose the
  informal statement into a *conceptual dependency graph* (nodes =
  definitions/structures/classes needed), ground each node by retrieving
  from Mathlib, then compose the formalization bottom-up with iterative
  refinement. Introduces **AriaScorer**, a semantic checker that retrieves
  Mathlib definitions for term-level grounding of the produced statement.
  Reports 91.6% compile / 68.5% final accuracy on ProofNet, 44.0% on FATE-X
  (baseline 24.0%), and 42.9% on a homological-conjectures set where
  baselines score 0%.
- **Reviewer's description check:** "dependency-graph autoformalization agent
  claiming concept grounding and semantic evaluation" — **accurate**.
  (Note: Bin Dong's group also authors LeanSearch-v2 — same lab, shared
  lineage worth a sentence.)
- **vs Wikibrain:** Aria constructs its concept→declaration join **on the
  fly, per statement** (ephemeral, learned, unaudited); the Brain *is* the
  join — persistent, human+AI-moderated, provenance-carrying, spanning
  Wikipedia/Wikidata/external DBs, reusable across tasks and agents.
  Aria's agent is the retrieval driver (agent-side, like ours), but its
  evaluation is single-system vs prior systems — there is **no control
  holding the same corpora unjoined**, so join value is not isolated.
  AriaScorer is a per-output semantic grader; our missing preregistered
  equivalence leg is the honest analog (we must not claim superiority
  there — they have a grader where we have a gap).

### 1.3 TheoremGraph — VERIFIED (existing anchor; description confirmed)

- **Citation:** Simon Kurgan, Evan Wang, Eric Leonen, Sophie Szeto, Luke
  Alexander, Artemii Remizov, Jarod Alper, Giovanni Inchiostro, Vasily
  Ilin. *TheoremGraph: Bridging Formal and Informal Mathematics.*
  arXiv:2606.25363 (v1 2026-06-24). Preprint.
- **What it does:** statement-level dependency graphs on both sides — 11.7M
  theorem-like environments / 18.3M candidate dependencies parsed from
  math arXiv, plus LeanGraph (388,105 decl nodes, 11.3M typed edges, 25
  Lean projects) — bridged by embedding generated NL "slogans" into a
  shared space; 47,952 LLM-judge-confirmed cross-register matches at
  cosine ≥ 0.8. Small retrieval/autoformalization study: 0.775 Recall@10
  for formal concept retrieval (name+signature+graph expansion), ~matching
  LeanSearch-v2's reranked 0.780; also the negative-transfer /
  typecheck-is-not-a-signal findings we already cite in §6.
- **Our report's description ("statement-level informal/formal graph +
  small autoformalization study") — still correct.** Unit is the
  *statement*, join is learned (embeddings + LLM judge), artifact is a
  dataset/graph, not agent tooling; no downstream proving; no no-join
  control.

### 1.4 LeanSearch-v2 — VERIFIED (existing anchor; description confirmed)

- **Citation:** Guoxiong Gao, Zeming Sun, Jiedong Jiang, Yutong Wang,
  Jingda Xu, Peihao Wu, Bryan Dai, Bin Dong. *LeanSearch v2: Global
  Premise Retrieval for Lean 4 Theorem Proving.* arXiv:2605.13137
  (v1 2026-05-13; v2 2026-05-14). Preprint.
- **What it does:** decl-level premise retrieval over a
  hierarchy-informalized Mathlib corpus. Standard mode =
  embedding+reranker (nDCG@10 0.62 vs 0.53 next-best); reasoning mode =
  iterative sketch-retrieve-reflect for *global* premise-set recovery
  (46.1% of ground-truth premise groups @10 on 69 research-level Mathlib
  queries vs 38.0% / 9.3% baselines). Downstream: a **fixed prover loop**
  — 20% proof success vs 16% next-best vs 4% no-retrieval.
- **Our report's description ("concept + global premise retrieval, fixed
  downstream proving experiment") — correct.** Learned system-side
  retrieval; formal-only corpus (informalization is a representation
  trick, not a cross-register join); its no-retrieval arm is a no-tools
  control, not an unjoined-corpora control.

### 1.5 ProofNetVerif / BEq+ — VERIFIED (existing anchor; description confirmed)

- **Citation:** Auguste Poiroux, Gail Weiss, Viktor Kunčak, Antoine
  Bosselut. *Improving Autoformalization using Type Checking.*
  arXiv:2406.07222 (2024; later versions). Introduces **BEq+** (automated
  semantic-equivalence metric correlating with human judgment),
  **ProofNetVerif** (3,752 labeled reference/prediction pairs for
  evaluating such metrics), plus ProofNet# and RLM25 benchmarks;
  type-check filtering + self-consistency gives up to +18.4pp on ProofNet.
- **Our report's description ("symbolic equivalence machinery + labeled
  evaluation data, from the Type Checking line") — correct.** Not a join
  system at all — it anchors the *semantic grader* axis and is the natural
  instrument for our ungraded equivalence leg.

### 1.6 DRIFT — VERIFIED (new; genuinely on-axis)

- **Citation:** Meiru Zhang, Philipp Borchert, Milan Gritta, Gerasimos
  Lampouras. *DRIFT: Decompose, Retrieve, Illustrate, then Formalize
  Theorems.* arXiv:2510.10815 (v1 2025-10-12; v4 2026-04-06).
  **ICLR 2026** (accepted).
- **What it does:** decomposes an informal statement into atomic
  concept-focused sub-queries, retrieves Mathlib premises per sub-query
  with a DPR retriever fine-tuned on Mathlib informal→dependency data,
  retrieves *illustrative* theorems showing premise usage, then
  formalizes. Roughly doubles premise-retrieval F1 vs DPR baseline on
  ProofNet; BEq+@10 gains of 42.25%/37.14% (GPT-4.1 / DeepSeek-V3.1) on
  out-of-distribution ConNF; also miniF2F-test.
- **vs Wikibrain:** concept-level *query decomposition* with a **learned**
  informal→formal join, run as a fixed system pipeline (not
  agent-selected tools); evaluated with BEq+ (a semantic grader — again
  ahead of us on that axis); baseline is weaker retrieval, not unjoined
  corpora.

### 1.7 Direct Dependency Retrieval (DDR) — VERIFIED (new; nearest analog to our verifier)

- **Citation:** Shaoqi Wang, Lu Yu, Siwei Lou, Feng Yan, Chunjie Yang,
  Qing Cui, Jun Zhou. *Improving Autoformalization Using Direct
  Dependency Retrieval.* arXiv:2511.11990 (v1 2025-11-15; v4 2026-01-01).
  Preprint (no venue found).
- **What it does:** instead of embedding-select RAG, a model *generates*
  candidate library dependency names directly from the informal statement
  and validates each against the actual library with an **efficient
  suffix-array existence check**; trained on a 500k-sample dependency
  retrieval dataset. Reports SOTA retrieval precision/recall and
  consistent single-attempt accuracy + multi-attempt stability gains for
  autoformalization over selection-RAG.
- **vs Wikibrain:** their generate-then-verify-existence loop is the
  closest published analog of `decl_exists` — independent convergence on
  *existence verification of generated names* as the anti-hallucination
  mechanism. Ours is agent-side and library-wide at inference; theirs is
  a trained system component. They do not have a curated concept join or
  a no-join control. Cite next to our verifier finding (the clean
  independent result), not just in related work.

## 3. Positioning takeaways for the contribution statement

1. **Concept grounding is no longer a novel idea — the causal test of the
   join is.** Four independent 2025–26 systems (CRAMF, Aria, DRIFT, DDR)
   converged on concept/dependency-level grounding for autoformalization,
   and all report gains. But every one of them joins per-query with a
   learned component and evaluates against *no-retrieval or
   weaker-retrieval* baselines. **None runs a control that holds the same
   informal and formal corpora accessible but unjoined — the Bridge
   experiment's D-vs-C/E contrast is, as far as we could verify, the only
   causal test of the join itself.** That, plus the join being a
   *persistent curated artifact* rather than per-query inference, is the
   contribution. (Single most important fact, if one must be picked.)
2. Frame honestly on the grader axis: Aria (AriaScorer) and DRIFT (BEq+)
   grade semantics; our preregistered equivalence leg went ungraded.
   ProofNetVerif/BEq+ is the ready-made instrument for closing that gap
   and should be named as such.
3. DDR's suffix-array existence check independently validates our
   verifier finding — cite it beside the 6.8%-hallucination result as
   convergent evidence that existence verification, not retrieval per se,
   kills citation hallucination.
4. Sub-communities are converging from three directions — RAG KBs
   (CRAMF/DRIFT/DDR), agents (Aria), datasets/graphs (TheoremGraph) — and
   Aria + LeanSearch-v2 share Bin Dong's group; position Wikibrain as the
   curated-database fourth quadrant, not a competitor inside any one.
